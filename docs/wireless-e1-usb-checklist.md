# E1：CarTransport 之后 Vezel 上的 USB 回归

分支 `claude/wireless-e1-transport`。同一分支上 targetSdk 提至 37：会话也要验证它（Android 16 上行为不应变化）。USB 现在走 `link/StreamTransport`（读写代码从 `CarLifeSession` 原样搬出）。线上不应有任何变化。车内一次会话，约 10 分钟。

## 构建

带临时版本号的测试 release 构建（例如 `1.1.9-e1test1`，versionCode 不动或本地 +1），版本修改不进提交。AA 证书在 `android/app/src/main/assets/aa/`（git 里没有）。覆盖安装在发布版之上。

## 车内

1. 手机解锁，数据线插入车机 USB。等车机屏幕上出现 AA。
2. AA 可见，画面不抖。触摸：滚动列表、打开地图、点按钮。
3. 声音：打开音乐（MEDIA），启动带语音提示的导航（TTS）。
4. 麦克风：按方向盘语音键，说一条命令，AA 应能识别。
5. Grace：拔出数据线，手机屏幕显示状态“USB 已丢失，AA 存活 N 秒”并倒计时；8 秒内插回数据线。AA 应无需重启即恢复（日志中“USB 在 grace 窗口内回来了”）。
6. 第二次断开：拔出数据线并等超过 8 秒。状态不应卡在“存活 0 秒”，插回数据线后会话应重新建立。
7. 手机上的 Headswap 画面：视觉上同之前（状态卡片，第 5 步中带重连指示器）。
8. 用按钮发送报告（含日志的 zip）。

## 日志里看什么（与 `logs/car-20261011-meta/headswap-20261011-161228.log` 对照）

- 视频模式描述之后新增一行 `会话: 传输=usb-aoa (<附件>)`。
- 新增 `WL link …` 和 `WL hs …` 行（阶段的结构化日志）。不应有其他新增行。
- `视频: 已发送帧=… 丢弃=… 队列=…`：帧速率和 `丢弃`（每会话不超过 1）与基准一致。
- “编码器码率”行为 0、`编码器/门控丢弃` 为 0/0。
- AA 统计行中的吞吐量同级（4.7–7.8 MiB/s）。
- 会话摘要：接收字节、触摸、帧；拔线时的关闭原因同之前：“附件已断开（broadcast）”或“读取 EOF（车机已断开）”。
- `python tools/logdigest.py <日志>` 无错误通过，输出与基准可比。
